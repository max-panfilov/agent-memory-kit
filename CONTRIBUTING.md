# Участие в разработке

## Порядок изменений

1. Создайте отдельную ветку и опишите задачу, границы и критерий приёмки.
2. Сохраните восемь публичных MCP-инструментов и совместимость их контрактов. Изменение контракта требует отдельного обсуждения и обновления документации.
3. Добавьте проверки нового поведения и обновите русские документы, включая ограничения и схемы.
4. Выполните все проверки из этого файла и откройте PR с точным SHA и списком результатов.

## Обязательные проверки

```sh
ci/verify.sh
python3 scripts/check_public.py
git diff --check
```

Дополнительно:

- вычитайте русский текст через `ru-check`;
- проверьте отсутствие секретов и частной инфраструктуры в дереве и истории;
- проверьте реальный MCP smoke и изолированное восстановление;
- проверьте итоговое отображение README и Mermaid на GitHub.

Сборка и тесты выполняются в доверенной self-hosted среде. Не используйте GitHub-hosted fallback.

## Требования к содержимому

- Все примеры и данные — синтетические.
- `shared_safe=True` не заменяет редакторскую проверку чувствительного текста.
- `approved`, `observed` и `draft` не взаимозаменяемы.
- Время измерений сопровождайте датой, окружением и ограничениями; один запуск не является SLA.
- Не добавляйте production-адреса, реальные токены, клиентские проекты, финансовые записи или частные журналы.

Код распространяется по лицензии MIT из файла `LICENSE`. Вклад принимается на тех же условиях.
