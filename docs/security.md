# Безопасность и границы доверия

## Модель доступа

Принципал состоит из `client_id`, хэша токена, разрешений `memory:read`/`memory:write`, проектов и приложений. Права проверяются при каждом вызове инструмента. Реестр проектов отдельно ограничивает доступные связи.

| Принципал | Права | Область |
|---|---|---|
| `demo-reader` | Чтение документов и памяти | Проект 1, `demo-app` |
| `demo-writer` | Чтение и добавление событий | Проект 1, `demo-app` |
| `other-writer` | Чтение и добавление событий | Проект 2, `other-app` |

Это демонстрация изоляции областей, а не персональная система учётных записей. Все принципалы работают в одном доверенном серверном процессе.

## Токены

В `content/principals.json` хранятся только SHA-256-хэши. Сервер сравнивает хэш через `hmac.compare_digest`. Токены не записываются в события, ответы или health.

Создать новые локальные значения можно так:

```sh
export DEMO_READER_TOKEN="$(openssl rand -hex 32)"
export DEMO_WRITER_TOKEN="$(openssl rand -hex 32)"
export OTHER_WRITER_TOKEN="$(openssl rand -hex 32)"
TOKEN_ENV_VAR=DEMO_WRITER_TOKEN python3 scripts/hash_token.py
```

Замените хэши в `content/principals.json`, а значения — только в локальном `.env` и `client.json`. Оба файла игнорируются Git. Не передавайте токен аргументом командной строки.

Демонстрационные токены из `.env.example` публичны по определению. Использовать их за пределами синтетического примера нельзя.

## STDIO

STDIO предназначен для доверенного локального процесса и не передаёт токен. `AGENT_MEMORY_STDIO_CLIENT_ID` выбирает принципала из реестра. Для writer по умолчанию используется `demo-writer`, поэтому запускать STDIO с реальными данными без отдельной оценки локальной границы нельзя.

HTTP с неизвестным токеном отклоняется. Reader видит семь read-инструментов и не получает `record_project_memory`. Дополнительно область проекта и приложения проверяется при каждом чтении и записи.

## Текст и секреты

Валидация отклоняет несколько типовых форматов приватных ключей и токенов. Это частичная защита от случайной публикации, а не классификатор конфиденциальности. `shared_safe=True` подтверждает намерение автора, но не доказывает безопасность содержимого.

Не записывайте:

- пароли, токены, приватные ключи и cookies;
- полные чаты, письма и персональные данные;
- финансовые записи и реквизиты;
- клиентские выгрузки и production-журналы;
- секреты в `source_refs`, поисковых запросах или именах проектов.

`mask_error_details=True` скрывает внутренние ошибки. Публичные коды ошибок не включают SQL, адреса или токены. Логи не должны содержать полезную нагрузку событий.

## Контейнеры

MCP работает от UID/GID 10001 с `read_only`, `cap_drop=ALL`, `no-new-privileges` и ограниченным tmpfs. PostgreSQL не публикуется на host. MCP слушает host только на `127.0.0.1`.

Rootless Docker не является песочницей: доступ к socket позволяет управлять всем daemon этой учётной записи. Не подключайте socket к непроверенным процессам.

## Перед реальным использованием

Нужен отдельный проект для:

- TLS и сетевой политики;
- хранения и ротации ключей;
- персональных ролей и аудита;
- ограничения ресурсов и rate limits;
- метрик, алертов и журналирования;
- зашифрованных копий за пределами хоста;
- регулярных обновлений и сканирования уязвимостей;
- восстановления с учётом других систем проекта.
